Credentials,
read and written.

Thirteen packages for the credentials a system must trust and the ones it must present — a certificate, a key, a request, a container, a revocation list, a token, a sealed envelope of JSON. They read what other tools write, and write what other tools read.

Nothing here picks an algorithm, invents a random number, or opens a socket.

Mooncred evidence iii

Verified, not claimed.

Every fixture in the suite was written by openssl, so each reader is measured against a writer it did not write.

openssl req -verify A request written here prints self-signature verify OK.
openssl pkcs12 -info Our container opens; a wrong passphrase gives Mac verify error — the negative case, proved too.
openssl pkeyutl -decrypt Both directions: a key wrapped here by RSA-OAEP-256 opens in openssl, and the reverse.
moon test --target all 137 tests pass on wasm-gc, js, native and wasm.

The revocation fixtures come from the same script: good, revoked, unknown and expired are each a case the reader has to get right, and a stale list is a case it has to refuse.

Mooncred what it will not do iv

Four refusals.

It chooses no algorithm.

The verifier is told which one to expect. A token that names its own is refused, because that is how a signature gets swapped.

It generates no entropy.

Salt, IV and content key are arguments. A test can then assert on a byte string instead of hoping.

It opens no socket.

revoke reads a list and judges an answer. Fetching either is the caller's business.

It implements no primitive.

RSA, ECDSA, Ed25519 and AES come from mooncrypt. ML-DSA certificates wait for it, rather than being faked here.
